# Stark

ПО для AR-инструкций по сборке: инженер загружает CAD-сборку, получает пошаговую
инструкцию, сборщик видит её в очках как 3D-модель на столе.

```
studio/   Stark Studio: Python + OpenCascade + веб-редактор (этот MVP)
spec/     формат пакета .stark (контракт между Studio и плеером)
player/   Stark Player: Unity для XREAL Air 2 Ultra + Beam Pro (впереди)
samples/  тестовая сборка «Редукторный модуль» (STEP) и готовый .stark
```

## Stark Studio: что умеет сейчас

1. **Импорт STEP** через OpenCascade: дерево сборки, имена (включая кириллицу), цвета, матрицы,
   одинаковые детали как экземпляры одной сетки.
2. **Нормализация**: мм, Z вверх (или Y, переключатель при загрузке), сборка стоит на столе.
3. **Классификация крепежа** по имени (болт, винт, гайка, DIN/ISO, M6…) и форме.
4. **Планировщик v0 «сборка через разборку»**: ищет детали, которые можно вынуть по прямой
   (±X, ±Y, ±Z и оси самой детали) без столкновений (FCL). Выбирает крепёж, потом детали,
   после снятия которых остальное не «висит в воздухе», потом верхние и мелкие.
   Одинаковые детали объединяются в один шаг, крепёж привязывается к шагу детали, которую держит.
   Обратный порядок = порядок сборки, обратное направление = анимация установки.
   Не вынимаемые детали и пересечения в CAD помечаются «проверить».
5. **Упрощение сеток** под бюджет очков (200 тыс. треугольников, крепёж упрощается сильнее).
6. **Веб-редактор**: 3D-вид с подсветкой текущего шага и анимацией установки, разлёт (explode),
   перетаскивание шагов, объединение/разделение, крепёж в отдельный шаг, инструмент,
   момент затяжки, проверки, подсказки ru/kk/en со счётчиком 80 символов.
7. **Подсказки**: Claude API, если задан `ANTHROPIC_API_KEY` (в модель уходят только названия
   деталей, инструмент и крепёж, без геометрии); без ключа работают шаблоны.
8. **Экспорт `.stark`** с проверкой (все детали есть в модели, у каждого шага есть подсказка и т.д.).

CAD-файл не покидает компьютер: сервер слушает только `127.0.0.1`, библиотеки 3D лежат локально.

На тестовой сборке из 17 деталей весь расчёт занимает меньше секунды, план совпадает с
физически правильным порядком (основание → подшипник → вал → шестерня → корпус →
кронштейны с болтами M4 → крышка с болтами M6 → маховик).

## Проверка на открытых сборках

`samples/fetch_open_samples.sh` скачивает две чужие открытые сборки (в репозиторий не кладём):

| Сборка | Деталей | Результат |
|---|---|---|
| AS1 (эталон OpenCascade / CAx-IF): плита, 2 уголка, тяга, 6 болтов, 8 гаек | 18 | 4 шага за 1 с: плита → уголки с 6 болтами → тяга с 2 гайками → 6 гаек снизу. Совпадает с ручной последовательностью |
| Планетарный редуктор NEMA17, 2 ступени, с рычагами (MIT) | 20 | 15 шагов за 0.5 с. Ступени собираются по оси, сателлиты ×3 одним шагом. 3 шага помечены «проверить»: в CAD солнечная шестерня врезана в вал и корпус |

## Запуск

Python 3.11+:

```bash
cd studio
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
stark-studio serve          # откройте http://127.0.0.1:8040
```

Или Docker: `docker compose up --build`, затем http://127.0.0.1:8040.

Без редактора:

```bash
stark-studio sample gearbox.step               # записать тестовую сборку
stark-studio process gearbox.step -o out.stark # STEP → .stark
stark-studio process my.step --up Y --llm      # Y вверх, подсказки через Claude
```

Тесты: `cd studio && pytest`.

Переменные окружения: `STARK_WORKSPACE` (где хранить проекты, по умолчанию `~/.stark-studio/projects`),
`ANTHROPIC_API_KEY` (подсказки LLM), `STARK_LLM_MODEL` (по умолчанию `claude-opus-5-5`).

## Ограничения v0 (что дальше)

* Планировщик проверяет только прямые пути вдоль осей. Гибкие детали, запрессовка, повороты
  при установке не моделируются: такие шаги помечаются «проверить».
* Устойчивость оценивается по касаниям, без физики и захвата (v1: подходы вроде ASAP/AssembleX).
* Подсборки пока раскрываются в плоский список деталей.
* Импорт GLB, QR-ссылка для загрузки на очки, отчёт пилота: следующие этапы.
