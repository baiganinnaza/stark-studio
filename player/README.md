# Stark Player (Unity 6, XREAL Air 2 Ultra + Beam Pro)

Плеер открывает пакет `.stark` из Stark Studio, ставит модель изделия на стол (6DoF-якорь)
и ведёт сборщика по шагам. Управление: жесты рук, поки-кнопки на столе, Bluetooth-кликер.
Формат пакета: [`spec/stark-format-v1.md`](../spec/stark-format-v1.md).

## Что умеет (веха 1)

| Функция | Как работает |
|---|---|
| Загрузка `.stark` | zip → manifest / steps / hints / model.glb, проверка версии формата и ссылок на детали. Модель грузится в рантайме через glTFast, не вшита в APK |
| Модель на столе | Взгляд на стол → метка-кольцо → щипок. Якорь AR Foundation (`ARAnchor`), модель не плывёт при обходе стола |
| Шаги | Текущие детали голубые и пульсируют, крепёж оранжевый с подписью «×4», готовые в цветах CAD, будущие скрыты (G = призраки 15 %) |
| Анимация установки | Деталь «прилетает» по `partPaths`/`insertPath` из Studio, цикл 2 с |
| Подсказка | Над моделью: «Шаг 3 из 8», текст (ru → kk/en по L), инструмент, крепёж и момент, чек-лист, пометка «не проверен инженером» |
| Разлёт | Кнопка «Разлёт» / X: детали расходятся по направлениям извлечения |
| Журнал сессии | Время на каждом шаге, возвраты, события → `persistentDataPath/Sessions/*.json` для отчёта пилота |

### Жесты

| Действие | Жест | Без рук |
|---|---|---|
| Поставить модель | Короткий щипок, глядя на стол | Enter / Пробел |
| Следующий / предыдущий шаг | Нажать пальцем кнопку «Далее» / «Назад» на столе, или **щипок со смахиванием влево / вправо** (как перелистнуть страницу) | → / ← , PageDown / PageUp (Bluetooth-кликер) |
| Вращать модель | Щипок рядом с моделью, держать ≥0.45 с и вести рукой вбок (только вокруг вертикали) | Q / E |
| Масштаб | Щипок двумя руками, развести / свести | + / − , 0 = 1:1 |
| Разлёт / собрать | Кнопка «Разлёт» | X |
| Переставить модель | Кнопка «Место» | R |

Короткое смахивание листает шаги и не вращает модель: вращение включается только после
удержания щипка 0.45 с. Две руки гасят одноручные жесты, разведение рук не листает шаги.
Пороги в `GestureSettings`, их надо подобрать на очках (этап 0).

## Запуск без очков (симулятор в редакторе)

1. Установите Unity **6000.0 LTS** через Unity Hub (модуль Android Build Support для сборки на Beam Pro).
2. Unity Hub → Add → папка `player/`. Unity скачает пакеты из `Packages/manifest.json`.
   На вопрос о новом Input System ответьте **Yes** (редактор перезапустится).
3. Меню **Stark → Create Player Scene**. Создаст `Assets/Scenes/StarkPlayer.unity`, материалы,
   URP-ассет и скопирует демо-пакет `samples/gearbox_module.stark` в StreamingAssets.
4. **Play.** Без XR запускается симулятор: комната со столом, камера на высоте глаз.

Управление в симуляторе:

| | |
|---|---|
| ПКМ + мышь | Смотреть вокруг |
| ПКМ + WASD | Ходить вокруг стола (проверка якоря) |
| Мышь | Правая «рука» над столом (белые точки = большой и указательный пальцы) |
| ЛКМ клик | Щипок (Tap): поставить модель |
| ЛКМ по кнопке на столе | Нажатие пальцем |
| ЛКМ + быстрый рывок влево / вправо | Смахивание: следующий / предыдущий шаг |
| ЛКМ зажать и вести | Вращение |
| Колесо мыши | Щипок двумя руками: масштаб |
| Клавиши | Как в колонке «Без рук» выше, плюс O = следующий пакет |

Мышь превращается в кадры рук и идёт через тот же `GestureRecognizer`, что и на очках,
так что симулятор проверяет настоящую логику жестов.

Свой пакет: поле **Editor Package Path** у компонента `StarkPlayer` (объект `Stark` в сцене),
или положите `.stark` в `persistentDataPath/Packages` (путь печатается в консоли).

## Тесты ядра (без Unity)

```bash
dotnet test player/dotnet/Tests     # .NET 8 SDK
```

25 тестов: формат и ошибки пакета, автомат шагов, журнал сессии, распознавание жестов
(tap, смахивание, удержание, две руки, потеря трекинга, гистерезис), поки-кнопки, анимация
и разлёт. Те же файлы видит Unity Test Runner (Window → General → Test Runner → EditMode).
`player/dotnet/Core` собирает ядро под netstandard2.1 + C# 9, как в Unity 6, и ловит
случайное использование API, которых в Unity нет.

## Проверка в Unity на GitHub Actions (без очков)

Workflow `player-unity` (GameCI) открывает проект в настоящем Unity, прогоняет EditMode-тесты
и PlayMode-тест `PlayerWalkthroughTests`: симулятор загружает демо-редуктор и планетарный
редуктор NEMA17 (собирается из открытого STEP прямо в CI), ставит модель на стол, проходит
все шаги, проверяет подсветку деталей и сохраняет скриншот каждого шага. Второй тест
подаёт в плеер кадры рук: щипок ставит модель, смахивание листает шаги, палец нажимает «Далее».
Скриншоты: Actions → запуск → артефакт **player-screenshots**.

Нужны секреты репозитория (Settings → Secrets and variables → Actions): `UNITY_LICENSE`
(содержимое `Unity_lic.ulf` после активации бесплатной лицензии в Unity Hub), `UNITY_EMAIL`,
`UNITY_PASSWORD`. Без них workflow пропускается с предупреждением.

## Сборка на Beam Pro

1. Скачайте XREAL SDK 3.1.0 (`com.xreal.xr.tar.gz`) с developer.xreal.com →
   Window → Package Manager → + → Add package from tarball.
2. **Stark → Configure Android Settings for XREAL** (minSdk 29, IL2CPP, ARM64, OpenGLES3, landscape).
3. Project Settings → XR Plug-in Management → вкладка Android → включить **XREAL**.
   Там же Project Validation → Fix All (это источник истины для настроек SDK).
4. Включить в XREAL-настройках трекинг рук и плоскостей (Hand Tracking, Plane Detection).
5. File → Build Profiles → Android → Build And Run на Beam Pro. На Beam Pro должно быть приложение MyGlasses.
6. Пакеты на устройство: по Wi‑Fi из Studio (ниже) или
   `adb push product.stark /sdcard/Android/data/kz.stark.player/files/Packages/`. Демо-редуктор вшит в сборку.

## Пакеты из Studio по Wi‑Fi (QR-код)

1. В Studio: кнопка **QR** → «Включить передачу». Компьютер и Beam Pro в одной Wi‑Fi сети.
2. Камерой Beam Pro отсканировать QR-код, открыть ссылку, нажать «Открыть в Stark Player».
   Плеер запоминает Studio (повторно сканировать нужно только после «Новый QR» или смены IP компьютера).
3. В Studio: **На очки**. Через 3 секунды пакет появляется в очках. Если модель уже стоит на столе,
   она остаётся на месте и на том же шаге: удобно править шаги в Studio и сразу смотреть в очках.

Что делает сборка: `StarkAndroidBuild` разрешает HTTP в локальной сети, добавляет разрешение INTERNET
и регистрирует ссылку `stark://link` в манифесте (свой AndroidManifest.xml класть не нужно).
`StudioLinkClient` добавляется к плееру сам. В редакторе Unity: вставьте адрес со страницы Studio
(`http://IP:8041/s/…`) в поле **Editor Pairing Link** компонента `StudioLinkClient` и нажмите Play.
Протокол: [spec/stark-link-v1.md](../spec/stark-link-v1.md).

Если XREAL SDK потребует другую версию AR Foundation, поменяйте её в `Packages/manifest.json`:
код использует только API, общие для AR Foundation 5.1 и 6.x.

## Что проверено, а что нужно проверить на очках

Проверено здесь: ядро (43 теста, вместе с протоколом связи со Studio), компиляция всего рантайм-кода (Core, Device, Presentation,
адаптеры, App) против UnityEngine; API пакетов (glTFast, Input System, AR Foundation,
XR Hands) заменялись заглушками по документации. В редакторе Unity проект ещё не открывался,
сборка на Android не делалась (нет Unity в облаке), редакторский скрипт `StarkSceneBuilder`
не компилировался.

**Нужно реальное устройство (этап 0, go/no-go):**

* Держится ли модель на столе при ходьбе вокруг (якорь XREAL), сколько времени ищется плоскость стола.
* Надёжность щипка на Air 2 Ultra: цель ≥9 из 10 при нормальном свете; пороги
  `PinchOnDistance` 2 см / `PinchOffDistance` 3.5 см подобрать по факту.
* Ложные срабатывания смахивания, когда в руке деталь или инструмент.
* Поки-кнопки 6×6 см: попадает ли палец, видно ли подписи на столе при поле зрения 52°.
* Читаемость текста `TextMesh` на оптике, размер строк.
* Привязки камеры `TrackedPoseDriver` (`<XRHMD>/centerEyePosition`) под XREAL.
  Если камера не двигается, заменить XR Origin на префаб из примеров XREAL SDK и назначить его в `XrRig`.
* QR-код из Studio открывает плеер (ссылка `stark://link` в манифесте), HTTP к Studio не блокируется,
  новая версия пакета подхватывается без потери места на столе.
* Производительность на Beam Pro (цель 60 fps), шейдеры glTFast в сборке
  (если модель розовая/невидимая: добавить шейдеры glTFast в Always Included Shaders).

## Архитектура

```
Assets/Stark/
  Core/          чистый C#, noEngineReferences: формат, шаги, жесты, разлёт, журнал (тестируется в dotnet)
  Device/        интерфейсы устройства: IPlacementService, IHandInput, ISystemInput
  Presentation/  Unity, не зависит от устройства: StarkPlayer, ModelView (glTFast), кнопки, подсказка
  Adapters/XR/        AR Foundation + XR Hands (XREAL сейчас, Quest/Pico через OpenXR позже)
  Adapters/Simulator/ симулятор редактора
  Adapters/Keyboard/  клавиатура и Bluetooth-кликер (и на устройстве)
  App/           StarkBootstrap: выбирает адаптер (единственное место, где они упоминаются)
  Editor/        Stark → Create Player Scene и настройки Android
  Tests/EditMode/  тесты ядра (общие с dotnet)
```

Ни один файл вне `Adapters/XR` не ссылается на AR Foundation / XR Hands, и ни один файл
не ссылается на XREAL SDK: он подключается как XR-провайдер. Это закреплено asmdef-ссылками.
Новое ODM-устройство = новый адаптер (реализация трёх интерфейсов) + строчка в `StarkBootstrap`.

Сцена собирается кодом (`StarkSceneBuilder`), поэтому `Assets/Scenes` и `Assets/Stark/Generated`
не хранятся в git. Файлы `.meta` Unity создаст при первом открытии, их стоит закоммитить.
